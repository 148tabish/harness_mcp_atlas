# harness-new

One task folder in, one packaged deliverable out. The harness owns everything
around harbor: it builds the task, starts the bridge the model needs, runs the
trials, grades them (pytest + codex rubric judge) and packages the job.

```bash
./setup.sh                                                  # once per machine
./run.sh --task input/wraysbury --model glm-5.3-flash -k 8 -n 2
```

## Prerequisites

| Requirement | Why | Check |
|---|---|---|
| Docker Engine + compose v2 | every trial is a container stack | `docker info`, `docker compose version` |
| User in the `docker` group | the harness drives docker directly | `docker ps` without sudo |
| `uv` | builds the venvs and fetches python 3.12 | `uv --version` |
| Python 3.12 | harbor requires it; uv fetches one if the system python is older | `uv python find 3.12` |
| ~40 GB free disk | images, light servers, trial artifacts | `df -h .` |
| 8 GB+ RAM | the agent stack plus the verifier | |
| Ports 8765 and 8766 free | Claude bridge and GLM bridge on the docker bridge address | `ss -ltn` |
| Outbound network | model APIs, image pulls, the codex judge | |

`./setup.sh --check` reports all of these and changes nothing.

## Credentials

**`.env` is the only file you edit.** `setup.sh` creates it from `.env.example`
on first run, reads it, and pushes what each component needs into its own config
(today that is `vendor/zbridge/.env`, which is derived and should not be edited
by hand). `run.sh` sources `.env` before every run. Re-running `setup.sh` keeps
generated secrets and only fills what is missing, so it is safe at any time.

```
.env  ──setup.sh──>  vendor/zbridge/.env   ZB_ZAI_API_KEY copied,
  │                                        ZB_BRIDGE_SECRET + ZB_THINKING_SIG_KEY
  │                                        generated once and kept
  └──run.sh──>  the run's environment      JUDGE_MODEL, CODEX_HOME, AWS_*
```

Each route needs its own credential. A missing one only disables that route; it
does not break the rest.

| Secret | Needed for | Where it goes |
|---|---|---|
| Codex login (`~/.codex/auth.json`) | the rubric channel | `codex login`, then the harness base64s it into the verifier as `CODEX_AUTH_B64` |
| Claude login | the `opus-5` route | `~/.claude/.credentials.json` or `CLAUDE_CODE_OAUTH_TOKEN` |
| z.ai API key | the GLM routes | `ZB_ZAI_API_KEY` in `.env`; `setup.sh` pushes it to the bridge |
| `ZB_BRIDGE_SECRET`, `ZB_THINKING_SIG_KEY` | GLM bridge auth | generated by `setup.sh`, never entered by hand |
| AWS credentials | only if you use the ECR image fallback | standard AWS env or `~/.aws` |

**Without a codex login the rubric channel is dropped** from both sides of the
reward, so runs are scored on Channel A alone. `setup.sh` warns when it is missing.

## What `setup.sh` does

1. creates `.env` from `.env.example` if it is missing, then reads it
2. checks every prerequisite above and stops on the hard ones
3. builds `.venv` and installs harbor from `vendor/harbor-0.23.0` (editable, no download)
4. builds the zbridge venv, pushes `ZB_ZAI_API_KEY` from `.env` into
   `vendor/zbridge/.env` and generates the two bridge secrets if absent
5. builds the Claude bridge venv
6. prints what is ready and what is missing

## The input contract

```
input/<task>/
├── instruction.md          # what the agent is told; keeps its own instruction-canary
├── task.toml               # [task] and [task.metadata] only
├── data/                   # evidence, mounted read-only at /workspace/data
├── world_data/             # overlay that seeds the Light apps
├── tests/
│   ├── test_outputs.py     # Channel A: deterministic checks, weights 1/3/5, guards negative
│   ├── test_weights.json   # components.traj_tests.tests + components.rubric
│   ├── rubric.json         # Channel B: criteria for the codex judge
│   └── oracle.json, old_env.json
├── solution/               # solve.py, gt_env.json, TRUTH.md - graders only
└── environment/Dockerfile  # the agent's image
```

`[task.metadata]` needs `apps` (the graded servers) and may add `mcp_servers`
(everything wired, graded apps plus ungraded distractors). Ports are read from
the light servers' own `entrypoint.sh`, so they cannot drift.

The harness rejects an input folder that carries `[agent]`, `[verifier]` or
`[environment]` blocks: it owns those. It also rejects a `gt_env.json` or
`oracle.json` found under `data/` or `world_data/`, where the agent would see it.

To turn an existing built task into an input folder:

```bash
.venv/bin/python -m harness.import_task --from ../fixed-tasks/<uuid> --name <name>
```

## Running

```bash
./run.sh --task input/wraysbury --model glm-5.3-flash -k 8 -n 2
./run.sh --task input/wraysbury --model opus-5 --effort low -k 8 -n 2
./run.sh --task input/wraysbury --only build            # materialise only
./run.sh --task input/wraysbury --only package --job out/jobs/<name>
./run.sh --task input/wraysbury --model opus-5 --no-package
```

| Flag | Meaning | Default |
|---|---|---|
| `--model` | `opus-5`, `glm-5.3-flash`, `glm-5.3`, `glm-4.6v` | `glm-5.3-flash` |
| `--effort` | reasoning effort, Claude only | unset |
| `-k` / `-n` / `-r` | attempts / concurrent / retries | 8 / 2 / 2 |
| `--threshold` | pass@k threshold | 0.7 |
| `--judge-model` | rubric judge | `gpt-5.6-sol` |
| `--only` | `validate`, `build`, `run`, `report`, `package` | all |

Output: `out/build/<uuid>/` (the task), `out/jobs/<job>/` (trials plus
`harness_summary.json`), `out/packaged/<uuid>/` (the deliverable).

## Scoring

- **Channel A, pytest** — `tests/test_outputs.py`, weights 1/3/5, guards negative.
  `channel_a = (earned − tripped guards) / total positive`. Deterministic checks
  only; they never raise.
- **Channel B, rubric** — `_judge/rubric_judge_cli.py` shells out to
  `codex exec -m gpt-5.6-sol` **inside the verifier container**, where the codex
  CLI is baked in and the login arrives as `CODEX_AUTH_B64`. Judgement only.
- **Combined** — `grade.py`: `reward = max(0, (wA·channel_a + wB·rubric)/(wA+wB))`
  over the components that produced a value. No codex login means the rubric
  channel is dropped from both sums, never scored zero.
- `ctrf.json` carries `overall_score = channel_a`.

## Models

`config/models.yaml` maps each model to a bridge. GLM-5.3 is text-only: images
reach it as `[image omitted: this model cannot view images]`. GLM-5.3-flash and
the `v` models read images. The runner patch in
`vendor/harness-levi-bridge/harbor_agent/openhands_bridge_agent.py` applies three
GLM-only settings that are needed for vision to work at all: `supports_vision`,
`force_string_serializer=False` and `max_output_tokens=16384`.

## Handing this to someone else

Copy the `harness-new/` folder, then on the new machine:

1. `./setup.sh --check` and fix whatever it reports
2. `./setup.sh` once, which writes `.env`
3. put the z.ai key in `.env`, run `codex login`, then `./setup.sh` again to push it through
4. `./run.sh --task input/<task> --model <model> -k 1 -n 1` as a smoke test

Two caveats worth stating plainly: the codex login is personal, so each operator
needs their own or the rubric goes unscored; and only one bridge can hold each
port, so two harness copies on one machine will share whichever bridge started
first.
